# XCover Android Auto receiver v0.3.0

This release makes the receiver application the dedicated Android launcher for the XCover Pro and publishes the accompanying performance and recovery workflow.

## Included

- the receiver is the Android `HOME` application; pressing Home always returns to the dedicated receiver surface;
- a receiver-owned **Apps** drawer replaces the daily One UI Home route;
- **System settings** is pinned as the first drawer item, with enabled launchable apps following in a two-column grid;
- card icon and label groups are centered, while cards continue to flow left-to-right and then downward;
- the drawer header contains a native Back action; Android Back returns to receiver home, and System settings returns to the drawer first;
- launcher, drawer, and System settings routes open directly with no parked-use confirmation;
- **Apps** and **Connect** share a 48 dp height, matched outer insets, and equal vertical padding in the 66 dp bottom bar;
- connection state is expressed by the Android Auto action itself (`Connect`, `Connecting…`, `Return`); no redundant ready label is rendered;
- one command provisions ART `speed` compilation and 0.5× Android animation scales after an APK update;
- One UI Home remains installed and enabled exclusively as a rollback launcher.

## APK

Asset: `open-headunit-tpms-xcover-v0.3.0-debug.apk`

This release retains package `com.andrerinas.headunitrevived.hfpslc`, version `3.2.0-hfp-slc` (`versionCode=95`), and the established Android debug signing certificate. Verify the attached `SHA256SUMS.txt` before installation.

## Verification

- clean application of both patches, complete unit-test suite, and GitHub debug APK assembly for the exact release candidate;
- package identity, signing certificate, local and installed APK hash, and launch on the physical Samsung `SM-G715U1`;
- physical launcher home, app drawer, direct System settings route, visible Back action, Android Back sequence, and rain-lock interception;
- launcher provisioning plus the matching One UI Home rollback route, with the receiver restored as the default launcher afterward;
- Android Auto connection and reconnection after an app restart with the exact `v0.3.0` candidate;
- receiver ART compiler filter `speed` and all three animation scales at `0.5` after the final installation.

Intercom audio, physical TPMS decoding, long-duration thermal behavior, rain-lock use during live projection, and vehicle ignition-interruption validation remain pending.

## Upgrade note

Install with `adb install -r` to preserve receiver settings and TPMS assignments. Re-run `scripts/configure-receiver-performance.sh <receiver-serial>` after updating so Android recompiles the new APK with the intended performance filter.
